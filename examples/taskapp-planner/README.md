# Example: TaskApp → Planner

A toy example for Shotgun: exposing a **TaskApp-shaped** API that's actually
backed by a **Planner** service — useful if you have clients built against
TaskApp's REST API and want to swap in Planner without rewriting them.

## Files here

- `taskapp-api.json` — a small TaskApp-style API (OpenAPI 3.0): list tasks,
  get/update a single task, and set a reminder.
- `planner-api.json` — the equivalent Planner API. Same domain, different
  field names (`title` vs `name`, `due_date` vs `deadline`), different
  method conventions (PUT vs PATCH), and no reminder endpoint.
- `mappings.toml` — generated by `shotgun init` against the two files above,
  then hand-edited where the auto-diff couldn't resolve things on its own
  (see the `edited = true` entries and their comments).

## What the auto-diff does and doesn't guess

Shotgun's matcher is deterministic: an endpoint auto-maps only when the
method + normalized path match exactly, or (failing that) the `operationId`
matches. Fields auto-map only on exact name + compatible type. No fuzzy
scoring. That leaves a human to handle:

- `GET /tasks/{task_id}` → `GET /items/{item_id}` — path structure matches
  (both are `GET /<collection>/{id}`), but the param names differ.
  `title`/`name` and `due_date`/`deadline` are the same field under different
  names — auto-diff listed them as defaults/drops; hand-converted to renames.
  `priority` has the same name but incompatible types (integer vs string) —
  flagged as a type conflict.
- `PUT /tasks/{task_id}` → `PATCH /items/{item_id}` — path matches but
  method differs (PUT vs PATCH), so auto-diff leaves it unmapped with a note
  rather than guessing. Confirmed by hand.
- `POST /tasks/{task_id}/remind` — no path or operationId match in the
  target spec (Planner has no reminder concept). Left with an empty target;
  returns 501 at runtime.

## Regenerating

```sh
cargo run -- init \
  --source examples/taskapp-planner/taskapp-api.json \
  --target examples/taskapp-planner/planner-api.json \
  --output examples/taskapp-planner/mappings.toml
```

## Running it

```sh
shotgun serve \
  --mappings examples/taskapp-planner/mappings.toml \
  --target-url https://planner.example.com \
  --listen 127.0.0.1:8080
```

Then point a TaskApp-speaking client at `http://127.0.0.1:8080` instead of
`api.taskapp.io`.
